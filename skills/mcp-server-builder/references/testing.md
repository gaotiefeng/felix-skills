# 验证与交付

## 内置示例的协议烟测

`assets/mock_api.py` 与 `assets/smoke.py` 是配套的示例测试工具。Python虚拟环境安装示例依赖后可测试两种语言；TypeScript项目需先npm ci及构建。

```bash
"<Python虚拟环境>/bin/python" "<技能目录>/assets/smoke.py" \
  --target python --project "<复制后的Python项目目录>" --output "<新结果JSON>"

"<Python虚拟环境>/bin/python" "<技能目录>/assets/smoke.py" \
  --target typescript --project "<已构建的TypeScript项目目录>" --output "<新结果JSON>"
```

脚本启动仅监听127.0.0.1随机端口的合成API，用官方Python MCP客户端启动指定示例并执行工具发现/调用，结束时停止模拟服务与所拥有的MCP子进程。需要Python SDK环境；Node项目本身不依赖Python运行。只针对包内get_order契约，开发新工具后须改写测试，不冒充任意MCP项目的通用测试器。

默认SDK自动协商；加 `--mode legacy` 对照较早协议。结果记录实际协商版本。不能凭两种模式样例通过就宣称所有客户端/协议功能兼容。

## 需要核对的可观察结果

- 工具发现：名称、描述、输入必填/类型/范围、输出schema与实际功能一致。
- 正常调用：MCP结构化结果与预期相同，并通过outputSchema验证。
- 错误参数：缺参、类型错误、路径非法在触发上游前失败。
- 上游失败：认证/权限、未找到、限流、5xx、超时、网络失败、无效/过大响应给出可辨识工具错误；不泄露正文或凭证，不将失败包装成成功。
- 恢复与副作用：错误后下一次正常调用成功，重定向不导致意外请求，重试数量与约定一致；写操作只用mock验证，真实动作按授权。
- 配置：缺少凭证时stderr有具体提示且stdout没有普通输出；不要求用户把密钥贴进聊天。

构建或单元测试不能替代MCP客户端实际调用。已有项目的测试以其契约为准，不要求机械复制本例所有异常。

### 需要登录或分页时，按契约补测

内置示例只覆盖固定Bearer Token和单条订单，不包含账号登录、租户、业务码或分页实现。生成这些能力后，为实际项目增加相应测试：

- 登录成功、字段/租户头正确、Token被复用；凭证错误、权限不足有可区分提示。
- HTTP成功而业务认证失败：走工具错误或实现中规定的受控续期；持续认证失败在重试上限后停止，后续正常调用仍能恢复。
- 令牌失效、限流、超时分别处理，不能都触发重登录；有并发刷新逻辑时验证只进行受控次数的刷新。
- 分页参数确实传到API；空列表、实体不存在、字段缺失和错误响应分别表达；仅返回约定字段。
- 新目录安装依赖后，最终command/args确实指向存在的解释器、脚本及配置；配置错误在stderr说明，不暴露密码。

模拟通过、真实登录、真实业务调用和图形客户端验收分别记录。真实数据测试只保留必要的验证元信息，避免把业务记录或凭证装进通用技能。一次项目验收不能代表其他API、客户端或独立模型也已通过。

## 客户端接入与常见问题

**为什么启动后没有普通提示？** stdio在等待客户端协议消息，不能通过print“启动成功”破坏stdout。

**为什么工具发现成功但调用失败？** 继续区分参数校验、上游鉴权、网络和响应契约；发现成功不证明业务接口连通。

**客户端配置统一吗？** 不统一。确认目标客户端和版本，按其官方格式给出command/args/env等实际设置，合并时保留已有服务。未指定客户端时交付这些启动参数，不把示意JSON称为可直接安装的通用配置。

**需要真实API才能开发吗？** 无需先执行真实业务。API契约已知时可先mock验证；真实连通、客户端界面验收及部署另行记录，不能互相替代。

**有本地页面地址就能接通吗？** 页面可能只提供前端。先从前端API配置/代理和后端路由确认接口地址；有源码时直接提取契约，登录字段仍不明时才追问。

**WorkBuddy如何接入？** 按其当前[官方MCP说明](https://www.workbuddy.ai/docs/zh/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/MCP-Guide)生成配置。若使用本地stdio，提供已存在的解释器/入口/私有配置绝对路径；不把CodeBuddy CLI或其他产品的配置位置混用。JSON格式有效或界面显示连接成功，都不能代替实际工具调用。

最终给出源码路径、精确启动命令、凭证配置方式、实际测试命令和结果、已知限制。用户只要求开发时，不自动注册全局服务、改客户端配置、部署或发送真实消息。
