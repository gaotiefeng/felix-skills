# API 契约、协议与边界

## 从外部接口到工具

收到API文档/curl时，先提取真实方法、固定Base URL、路径/查询/请求体、认证方式、响应字段及错误样例。curl中的真实Token改为配置引用，不写进源码和示例。资料缺失时明确缺哪一项；可以先实现mock，不能编造已有真实接口。

已有项目先定位相关路由/Controller、请求/响应类型和必要的服务逻辑；前端 API 客户端、环境配置或代理可帮助确认实际后端地址及请求头。不要把浏览器页面路径当作 API Base URL，也不必先让用户重新整理代码中已有的文档。

不要把任意HTTP方法、任意URL与任意请求体直接暴露成一个万能工具。为用户任务设计具体工具，路径标识符做类型、长度和字符限制；查询、发送通知、创建、删除分别声明其行为。工具说明和readOnly等注解不能代替服务端权限控制。

以实际处理逻辑判断工具是否只读，不单凭GET/POST命名。状态枚举、参数含义和精确/模糊匹配以契约或源码为依据；筛选类型参数不一定等于返回记录的状态字段。

预期上游失败通过SDK的工具错误通道返回可读原因和下一步；协议请求无效由SDK处理。超时、限流、权限不足与响应无效分别说明。错误日志和工具输出不包含凭证或原始敏感正文。只对有依据的幂等操作设计有限重试，遵守429和Retry-After；示例选择不重试。

## 登录、凭证与租户

先确认是现成Token、账号密码换Token、Cookie还是其他认证。账号密码方式还需登录方法/路径、请求编码与字段、成功业务码、Token路径、请求头，以及租户或验证码要求。`username`、`data.accessToken`等常见字段只能作为标注待确认的示例，不声称只填账号密码就能连通。

凭证通过环境变量或本地私有配置加载；示例保持空值。交付说明写清配置文件绝对路径、如何创建及修改后是否需重启；私有文件设适当权限并排除版本跟踪和分发。检查配置错误时不要回显包含密码的原始行。环境变量示例文件不代表程序会自动加载它。

租户信息从已确认的配置或用户选择获取，不从订单号猜租户，不允许模型任意切换租户绕过原系统权限。若是单租户工具，租户头可固定在本地配置中，无需作为模型参数。

需要会话复用时，令牌缓存与刷新由API客户端管理。只在明确认证过期且操作可安全重试时设计一次有上限的刷新/重登与重查；登录本身失败立即返回，不循环尝试。权限拒绝不当作认证过期；限流、5xx和超时不触发重新登录。并发调用共享会话时协调刷新，避免同时重复登录。仅Token模式过期时应提示更新配置，不自动改用另一套凭证。验证码或交互登录缺支持时明确说明，不跳过或伪造校验。

## 业务码、分页与输出

HTTP成功不一定表示业务成功。例如HTTP 200中 `{"code":401,"data":null}` 应按该API契约作为认证失败；只有契约明确 `code=0` 才以0为成功标准。错误结构与正常数据分别验证，不把空data当成“无订单”，也不直接透传含敏感内容的msg。

分页接口确认页码起点、页大小限制、列表/总数位置与排序；只返回本页，除非用户需要且实现了受控的完整遍历。列表为空说明当前筛选和页码无结果，不能直接证明实体不存在；详情的“不存在”按原接口独立处理。确认需求后提供字段选择，缺失值保留缺失含义，不默认为0或编造名称。工具输出schema须与实际选择的字段一致，备注或其他业务文本仍然只是数据。

## 内置模拟API约定

- `GET /orders/{order_id}`，Bearer Token从API_TOKEN读取。
- 200、application/json：`{"order_id":"TEST001","status":"in_transit"}`；两字段非空字符串，响应标识须与请求一致。
- 401/403、404、429、500分别验证认证、权限、未找到、限流和上游异常。
- 另测非JSON、结构错误、错误标识、过大响应、重定向与慢响应；模拟凭证不是真实密钥。
- 示例限制响应64KiB、可配置超时、无自动重试；这些是代码策略，不是所有API或MCP的标准值。

## 协议与传输版本

[MCP官方规范入口](https://modelcontextprotocol.io/specification/latest)是规范依据，查看时记录实际重定向版本。本版核对日期2026-10-22，规范入口为2026-07-28；内置示例按官方v2 SDK开发。较早协议的会话/initialize流程与新版不同，协议细节交由SDK处理，不能把旧握手当成所有版本的固定要求。

[Tools规范](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)定义工具描述、inputSchema/outputSchema及调用结果；[传输规范](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports)区分stdio与Streamable HTTP。

stdio由客户端启动本地子进程；Streamable HTTP是MCP自身的远程传输。一个stdio MCP调用外部REST API，仍然是stdio服务，不等于已提供远程MCP端点。普通HTTP健康检查成功也不能证明tools/list和tools/call可用。

用户需要远程服务时，按对应SDK官方HTTP实现开发，确认客户端支持版本，并另外实现服务访问鉴权、权限/租户隔离、Origin等传输要求与连接生命周期。上游API_TOKEN只用于上游接口鉴权，不自动成为远程MCP调用者的身份认证。本版未内置已验收的远程服务模板。
