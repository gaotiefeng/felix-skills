# MCP 取证约定

在存在可用连接时阅读。这里定义的是能力要求与取证方法，不是已经实现的 MCP server，也不保证目标平台开放这些接口。

## 发现并映射能力

先查看当前环境实际提供的工具说明和参数。将下列能力映射到真实工具；不虚构工具名，不假定有数据库、云平台或日志权限，不把示例参数当成接口规范。

| 能力 | 最小查询范围 | 必须保留的上下文 |
|---|---|---|
| 日志检索 | 环境、服务、起止时间、实例/关联键、条数上限 | 原始时间、记录 ID 或查询条件、实例、版本、分页和截断状态 |
| 告警详情 | 告警 ID 或服务与时间窗口 | 规则、阈值、评估窗口、首次触发、恢复时间、关联对象 |
| 指标查询 | 指标、标签过滤、时间窗、步长、聚合 | 单位、分母、采样间隔、缺失点、标签范围 |
| 发布/变更查询 | 服务、环境、窗口或版本 | 版本、提交 ID、配置差异、部署批次、目标实例、接流量和回滚时间 |
| 链路追踪 | trace ID 或已限缩的错误请求窗口 | 调用关系、失败位置、耗时、采样信息、请求与实例关联 |
| 工单/事件读取 | 指定事件 ID 或明确范围 | 用户报告时间、影响陈述、人工操作及其执行结果 |

缺失一种能力时，记录相应盲区，继续使用其他来源。不要通过申请更广权限或切换生产账户自行扩大任务。

## 查询策略

1. 用已有告警或用户材料定位窗口和受影响对象。查询中明确环境，避免混用测试与生产同名服务。
2. 先取告警规则、错误趋势和窗口内变更摘要，再围绕首次异常查询有限日志。发现线索后使用 trace、实例或版本过滤；不要全量导出日志再筛。
3. 为验证某个候选原因补充有区分力的数据，例如同窗口新旧版本的错误率或同一请求的下游跨度。保持比较双方流量、窗口及聚合口径可比。
4. 查询前确定实际可控的时间窗和记录上限，按工具分页规则取数据。摘要不能替代尚未读取的页面；达到上限仍未覆盖时，缩窄查询或报告覆盖限制。扩大窗口要服务于具体假设。

暂时性错误可按接口约定有限重试；权限不足或参数不支持时不重复同一请求。429 按平台退避要求处理，不能借多连接绕过限制。记录失败和未查询到的部分，不能拿它们证明没有异常。

## 证据保存

报告至少保留工具/数据源、必要的脱敏查询条件、查询时刻、事件时间范围、记录定位和覆盖限制。不要把密钥或含凭证的完整 URL 写入报告。只有临时查询结果且没有持久定位时，明确说明；用户要求保存报告时可保存相关的最小脱敏摘录。

时间线使用事件时间；查询时刻仅用于说明数据新鲜度。比较恢复状态时确认最新数据覆盖的时刻，不能用旧快照证明当前恢复。
