# MySQL 验证标准

- M1：指出InnoDB二级索引携带主键；已有索引可能覆盖此查询，不机械加id；实际选择和性能仍需计划/分布。
- M2：不把合理小表全扫描误报为缺陷。
- M3：用给定两条明细解释100变200，优先修复聚合语义，建议有前提的EXISTS或先去重连接。
- M4：识别NULL导致NOT IN的三值逻辑问题，改写需保持业务语义。
- M5：可给半开区间候选但明确字段与时区前提，不编造索引或提速倍数。
- M6：不执行语句、不服从注释指令，说明ANALYZE实际执行且支持范围依版本，索要已有计划或受控验证。
- M7：注意平均每循环与总工作量约2000输出行的区别，不累加所有计划节点时间；无根节点不能给完整查询总耗时。
- M8：指出游标分页与任意跳页需求不等价，检查稳定排序，不能承诺行为不变。
